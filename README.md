# SecureFlow: Візуалізатор шляхів атаки та захисту у вебзастосунках

## Команда
- Костюк Поліна
- Штомпіль Владислава

## Опис

SecureFlow — це інтерактивна платформа для моделювання загроз і візуалізації кібератак у вебзастосунках.

- **Проблематика**: Розробники часто не розуміють у реальному часі, на якому саме етапі ланцюга компрометації спрацьовує певний захисний механізм.
- **Призначення**: Застосунок створений для студентів, викладачів та junior-розробників, щоб наочно демонструвати життєвий цикл атак (на основі OWASP Top 10) та те, як засоби безпеки розривають цей ланцюг.

## Ролі та права доступу

- **Гість (Guest)**: Перегляд загальної бази опублікованих вразливостей (`is_published=true`), публічних кейсів та OpenAPI-документації.
- **Користувач / Студент (User)**: Доступ до інтерактивної пісочниці, створення власних сценаріїв загроз (чернеток), запуск симуляцій атак, зміна параметрів захисту (вмикання/вимикання валідації чи параметризації), перегляд історії власних симуляцій.
- **Адміністратор (Admin)**: Повний контроль над базою сценаріїв загроз (включно з публікацією та редагуванням чужих сценаріїв), перегляд логів безпеки, налаштування інтеграцій сповіщень.

## Основний функціонал

- **Модуль симуляції атак**: Покроковий розбір векторів (наприклад, SQL Injection, XSS, Broken Access Control, CSRF, SSRF) з фіксацією результату перехоплення або прориву.
- **Інтерактивні бар'єри захисту**: Перемикання між захищеним і вразливим режимами в реальному часі з миттєвим логуванням спроб атак.
- **Система автентифікації (JWT & Session)**: Безпечний вхід, видача токенів та перевірка прав доступу залежно від ролі.
- **Журнал симуляцій та безпеки**: Зберігання історії запусків атак, аналіз векторів та корисного навантаження.
- **Інтеграція з Discord-ботом**: Генерація автоматичних сповіщень про події безпеки через Webhook.

## Встановлення та запуск проєкту

### 1. Клонування репозиторію
```bash
git clone https://github.com/polinakostiuk/Async-Sunsets.git
cd Async-Sunsets
```

### 2. Створення та активація віртуального середовища
```bash
# Windows
python -m venv .venv
.\.venv\Scripts\activate

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Встановлення залежностей
Усі залежності зафіксовані у файлі `requirements.txt`:
```bash
pip install -r requirements.txt
```

### 4. Налаштування змінних середовища (.env)
Проєкт використовує бібліотеку `python-dotenv` для безпечного керування конфіденційними налаштуваннями.

Створіть власний файл `.env` на основі шаблону `.env.example`:
```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux / macOS
cp .env.example .env
```

Змінні середовища у файлі `.env`:
| Змінна | Опис | Приклад значення за замовчуванням |
|---|---|---|
| `SECRET_KEY` | Секретний ключ Django для криптографічного підпису | `django-insecure-...` (згенеруйте надійний для продакшну) |
| `DEBUG` | Режим налагодження (True/False) | `True` |
| `ALLOWED_HOSTS` | Дозволені хости через кому | `localhost,127.0.0.1` |
| `LOG_LEVEL` | Рівень логування застосунку | `INFO` (або `DEBUG`, `WARNING`, `ERROR`) |
| `DISCORD_WEBHOOK_URL` | URL вебхука Discord для нотифікацій | `https://discord.com/api/webhooks/...` |

> ⚠️ **Важливо**: Файл `.env` додано до `.gitignore`, щоб запобігти потраплянню конфіденційних даних у Git-репозиторій. Не зберігайте реальні секретні ключі та токени у відкритому доступі!

### 5. Застосування міграцій бази даних
```bash
python manage.py migrate
```

### 6. Запуск сервера розробки
```bash
python manage.py runserver
```
Сервер буде доступний за адресою: `http://127.0.0.1:8000/`.

## Документація API (OpenAPI, Swagger UI, ReDoc)

Проєкт підтримує автоматичну генерацію специфікації OpenAPI 3.0 за допомогою бібліотеки `drf-spectacular`.

### Інтерактивні інтерфейси документації:
- **Swagger UI**: [http://127.0.0.1:8000/api/docs/swagger/](http://127.0.0.1:8000/api/docs/swagger/)
- **ReDoc**: [http://127.0.0.1:8000/api/docs/redoc/](http://127.0.0.1:8000/api/docs/redoc/)

### Отримання схеми OpenAPI:
- У форматі **YAML/JSON через endpoint**: [http://127.0.0.1:8000/api/schema/](http://127.0.0.1:8000/api/schema/)
- Експорт схеми у файл через CLI:
  ```bash
  python manage.py spectacular --file schema.yml
  ```

### Опис ключових ендпоінтів ресурсу Scenarios (`/api/scenarios/`):
| Метод | URL | Опис | Доступ |
|---|---|---|---|
| `GET` | `/api/scenarios/` | Отримати список сценаріїв (з фільтрацією за `vulnerability_type`, `severity`, пошуком `search`) | Публічний (Гість бачить опубліковані, Студент — опубліковані + свої, Адмін — усі) |
| `POST` | `/api/scenarios/` | Створити новий сценарій атаки | Потрібна автентифікація (Студент створює чернетки, Адмін може одразу публікувати) |
| `GET` | `/api/scenarios/{id}/` | Отримати деталі конкретного сценарію | Публічний для опублікованих; лише автор або адмін для чернеток |
| `PUT` | `/api/scenarios/{id}/` | Повне оновлення сценарію | Лише автор або адміністратор |
| `PATCH` | `/api/scenarios/{id}/` | Часткове оновлення полів сценарію | Лише автор або адміністратор |
| `DELETE` | `/api/scenarios/{id}/` | Видалити сценарій | Лише автор або адміністратор |
| `POST` | `/api/scenarios/{id}/simulate/` | Запустити симуляцію атаки з payload та перевіркою бар'єру захисту | Потрібна автентифікація |
| `GET` | `/api/scenarios/{id}/history/` | Отримати історію симуляцій сценарію | Потрібна автентифікація |
| `POST` | `/api/auth/token/` | Отримати пару JWT токенів (Access + Refresh) | Публічний |
| `POST` | `/api/auth/token/refresh/` | Оновити JWT токен | Публічний |

## Логування

У проєкті налаштовано структуроване дворівневе логування (консоль + файл `logs/secureflow.log`).

- **Рівні логування**:
  - `DEBUG`: Діагностичні повідомлення, виклики симуляцій та трасування параметрів.
  - `INFO`: Успішне створення, оновлення, видалення сценаріїв, а також симуляції, в яких захисний бар'єр успішно нейтралізував загрозу (`MITIGATED`).
  - `WARNING`: Спроби прориву захисту під час симуляції з вимкненим бар'єром (`BREACHED`), помилки валідації вхідних даних або підозрілий ввід.
  - `ERROR`: Критичні системні збої та непередбачені помилки середовища.
- **Безпека**: Логи не містять конфіденційних даних (паролі, JWT-токени не записуються; розмір та вміст payload санітизується).

## Тестування та звіт про покриття

Автоматизоване тестування реалізовано за допомогою `pytest` та `pytest-django` з використанням фікстур (`conftest.py`).

Тести покривають:
- Усі HTTP-методи (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`) та кастомний екшен `simulate`.
- Позитивні сценарії (CRUD-операції, перегляд публічних даних, симуляція блокування загрози).
- Негативні сценарії (неавтентифікований доступ `401`, недостатні права доступу `403`, неіснуючі об'єкти `404`, помилки валідації `400`).
- Рольовий доступ (Guest vs Student vs Admin).
- Ендпоінти OpenAPI-документації (`/api/schema/`, `/api/docs/swagger/`, `/api/docs/redoc/`).

### Запуск тестів:
```bash
pytest -v
```

### Запуск тестів із заміром покриття (pytest-cov / coverage):
```bash
pytest --cov=scenarios --cov-report=term-missing
```
